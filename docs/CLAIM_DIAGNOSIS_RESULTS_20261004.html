Changes retained from this run

  • Explanation handoff: replace an explicitly unresolved or failed initial explanation only after the existing same-label confirmation gate passes. Keep an already-directional explanation. A 198-case saved replay changed 12 reasons, zero labels and zero confirmation decisions. Some replacement reasons are still partial or wrong; this fixes a handoff inconsistency, not semantic truth.
  • Canonical protocol: validate canonical-claim-conditions-1 for the canonical experiment, instead of requiring the noncanonical identifier. Both directions and tamper rejection pass real-gate tests. This experiment remains evaluation-only.

Pushed branch: release-candidate

bb151aa is one commit ahead of main 43bb84f, changing 16 files (+555/−36). All changed implementation, dependency and test files were reviewed against main and the local working code.

  • Distinct selection grammar: all 1-4 ID subsets in sorted order, for the exact supported selection schema and at most 64 catalogue IDs. Other schemas use the old decoder and validators.
  • Distinct audit citations: enumerate legal lists for at most six selected IDs; reject remaining duplicates without a full retry that might erase substantive objections.
  • Opt-in audit-only-1 keeps baseline proposer/relation schemas and changes the challenge to a focused objection audit; it is not identical to our current focused/aligned pipeline.
  • Audit-only challenge budget is 512 tokens versus 384 for focused audit. With repair explicitly disabled and proposer/verifier disagreement, skip the challenge that cannot pass the existing gate.
  • Dependency pins and environment checker move torch 2.5.1+cu121 to 2.7.1+cu128, torchvision 0.20.1+cu121 to 0.22.1+cu128; lockfile changes with them.
  • The branch does not contain our later local question-routing, completion, condition-evaluation or latest unresolved-explanation handoff changes. Seven tracked implementation/CLI paths overlap our local edits.

Review conclusion: No definite new functional defect found in the reviewed diff and exercised tests. The grammar/citation changes directly target observed operational failures. No semantic accuracy gain is established by these tests; do not replace the current checkout with this older-baseline branch.

Its four new test modules passed 27 collected tests in an isolated export using our existing environment. This does not validate the branch’s new CUDA/PyTorch installation, real-model selection behavior, runtime improvement, or semantic accuracy. No such new benchmark results were present in the reviewed commit.

The most useful candidate for a later isolated comparison is the distinct-ID grammar: it addresses a failure observed in our pilot without weakening visibility or coverage checks. It constrains selection to ascending IDs, so every eligible subset remains possible but generation order changes. Above 64 IDs or for a changed selection schema it falls back to the original decoder. Audit-only is a separate ablation against baseline; comparing it to our focused mode also changes upstream reading fields and instructions.

Both GPU experiments finished; no further experiment started. Existing changes remain local and the current branch remains main. No merge, dependency installation or push was performed.
